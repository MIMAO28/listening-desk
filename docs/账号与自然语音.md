# 账号、学习记录与自然语音

## 数据在哪里

GitHub Pages 托管静态网页。Supabase 提供邮箱认证和云端 PostgreSQL。
本机电脑无需常开。各访客浏览器负责音频生成与播放。

`public/account-config.json` 中只有项目网址与 publishable key，按设计公开。
不要写入数据库密码、service_role/secret key、SMTP授权码或管理访问令牌。

## 一次性设置

1. 为主要用户选择较近的项目地区；本项目面向中国用户优先新加坡，最终以真实网络测试为准。
2. 在 SQL Editor 执行 `supabase/migrations/202610280001_learning.sql`。
3. 邮箱/密码注册保留邮件确认；设置自定义SMTP后才能向项目团队以外的邮箱发送验证邮件。
   邮件模板使用`supabase/email-templates`中的中文模板，Subject分别为“听写练习台｜注册验证码”和“听写练习台｜找回密码验证码”。保留`{{ .Token }}`，注册及恢复密码在网站内输入OTP，不依赖外部确认链接。
4. Site URL 与 Redirect URL 都配置为 `https://mimao28.github.io/listening-desk/`。
5. QQ邮箱SMTP可用 `smtp.qq.com:465`；用户名/发件人均为完整邮箱，密码填写第三方授权码。只在服务商后台输入，不写入仓库。
6. 在正式网址注册、输入邮件验证码、登录并检查一句，再刷新学习面板验证。至少用两个账号测试隔离。验证码错误/失效有提示，重发按钮有60秒冷却。

Supabase 免费项目有额度和闲置暂停限制；自定义发信邮箱也有自己的发送限制。
新加坡不能保证中国所有运营商可达；不应将代理下的成功请求当成直连证明。

## 记录与计分

- 游客不上传学习记录。登录状态由认证SDK保存在当前浏览器，可退出登录。
- 材料原文、各句听写与页面设置不上传，刷新后清空；云端保存材料标题、语言、时间、句数和词语计数。
- 练习页可见且处于播放或最近60秒有听写输入时计时；每15秒及离开页面时尝试同步。
- 关闭网页/断网可能使最后一段未完成请求的统计丢失；失败会提示重试，不宣称离线同步。
- 同一轮同一句重复检查保留最高正确词数，只补新增分数。新一轮练习可再次计分。
- 英语按单词计分，日语按字符计分；忽略大小写与标点。对齐用最长公共子序列，避免一个漏词导致后面全部被判错。
- 等级公式为 `round(200 × level^1.5)`，20个头衔，与参考站公开等级逻辑一致。等级是练习积分，不等于CEFR。
- 不提供排行榜或防作弊承诺。用户可以自行提供原文，个人积分不适合作为考试成绩。
- 上海时区计算日期与打卡；至少检查一句才计入连续学习天数。

RLS限制用户只能读自己的记录。普通用户禁止直接写表，写入经过检查账号归属的RPC。
`node scripts/test-learning-database.mjs` 在本地PostgreSQL引擎测试两个账号和游客权限。

## 自然音色

英语新增Kokoro Heart、Bella、Michael、Fenrir、Emma、Isabella、George、Fable。
它们与参考站公开标识为同一预设音色系列，不声称配音参数或最终波形完全一致。

模型和运行库同站托管，材料不发送到语音服务器。初次约100MB资源下载需用户点击；随后本机生成整篇音频，全部完成才启用播放。已准备句子直接启动AudioBuffer，三遍、切句与连播沿用同一播放队列。
CPU/内存限制会影响准备速度；整篇音频内存上限96MiB，超过时提示拆篇。初次下载、本机合成和设备音频唤醒仍需等待，不承诺任何环境绝对零延迟。
