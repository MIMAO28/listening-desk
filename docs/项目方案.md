# 个人精听练习工具：第一版方案

日期：2026-10-25。状态：已实现本地语音试用版。下文保留原始设计范围；实际启动与当前限制见 [开始使用](开始使用.md)。

## 1. 做成什么样

在 Windows 电脑上打开浏览器，粘贴或导入一篇文字，程序自动分句。选择声音后，逐句朗读；用户在右侧听写，遇到困难可以重听、放慢、切换句子，练习内容会保存在当前浏览器。

已确认：文字输入、Windows 浏览器、边学边做。第一版以英语验收，保留语言选择以便扩展；具体口音与声音在本机试听后选择。

按用户文字要求采用**左侧原文、右侧听写**。参考截图中的左右顺序不同，只借鉴其操作逻辑。参考网址未能在线读取，不推断其隐藏功能。

## 2. 第一版范围

| 功能 | 第一版行为 |
|---|---|
| 导入文字 | 粘贴文字，或选择 UTF-8 的 `.txt` 文件；导入表示浏览器读取本地文件 |
| 自动断句 | 根据标点与语言规则生成句子列表，导入后先预览；允许手动修改分行，每个非空行为一句 |
| 逐句播放 | 点击句子选中，再按播放；一句结束后停下，给听写留时间 |
| 上一句/下一句 | 立即停止旧句并播放相邻句；首尾禁用对应按钮 |
| 播放/暂停 | 当前句播放中可暂停，再次点击从暂停位置继续；完整播完后点击则从句首开始 |
| 重复三次 | 从当前句开头重新完整播放三遍，每遍之间间隔 0.8 秒，结束后停下；显示 1/3 等进度 |
| 语速与声音 | 先提供 0.75、1、1.25、1.5 档及可用英语声音列表，实际效果本机试听 |
| 原文区 | 当前句高亮、句号编号、点击选句；可隐藏全文、临时查看当前句 |
| 听写区 | 每篇材料一个连续文本框；切句与重听不清空，也不抢走输入焦点 |
| 保存与恢复 | 保存材料、听写内容、当前句和设置；重新进入恢复练习位置，但不自动出声 |
| 备份 | 导出、重新导入 JSON 练习备份，避免把浏览器存储当成唯一副本 |
| 快捷键 | 初定 Alt+J 上一句、Alt+K 播放/暂停、Alt+L 下一句、Alt+R 重复；实现时在 Edge/Chrome 和输入框内验证冲突 |

初始材料上限拟定为 100 KB 且不超过 20,000 字符；超限、空白文件、错误编码应给出明确提示。上限是实现起点，按试用调整。

第一版以一篇真实材料完成练习为目标。账号登录、多人同步、手机安装包、网站抓取、PDF/Word 解析、语音识别、AI 评分等放到后续需求中讨论。

## 3. 界面安排

页面由三块组成：

1. 顶部：材料标题、导入入口、声音选择和播放控制，始终可操作。
2. 左栏：可滚动句子列表、当前句高亮、隐藏与显示按钮。
3. 右栏：听写输入框和自动保存状态，输入时可使用播放快捷键。

初始两栏等宽；优先保证 1366×768 与 1920×1080 桌面窗口可用。使用清晰的字号、足够行距和少量颜色，避免装饰挤占练习空间。

“隐藏原文”要隐藏实际文本及其可访问描述，保留句号占位，避免当前句提示或辅助标签泄露答案。导入预览可以查看原文，正式练习前再隐藏。

## 4. 技术路线与理由

| 部分 | 建议 | 在这个项目中的作用 |
|---|---|---|
| 界面 | React | 把原文、听写、控制栏拆成组件，统一管理当前句与播放状态 |
| 代码 | TypeScript | 用类型描述材料与状态，便于定位错误；只学习当下用到的语法 |
| 工程 | Vite | 创建项目、启动本地开发服务、打包网页 |
| 外观 | 普通 CSS | 双栏和控制按钮直接实现，先保持依赖简单 |
| 断句 | `Intl.Segmenter` | 先用浏览器的语言分句能力，再提供手动修正入口 |
| 语音试验 | `speechSynthesis` | 通过浏览器已有声音直接朗读，无需先配置应用自己的语音 API 密钥 |
| 本地保存 | `localStorage` + JSON 备份 | 第一版保存小规模文本与练习状态；以后有音频文件缓存时再评估 IndexedDB |

选择这条路线是为了尽快做出可练习的小闭环，同时学习界面、事件、状态与数据保存。先补够 HTML/CSS、JavaScript 与 React 的必要概念，不要求先完成一整套前端课程。

### 语音方案要先过一道实际验收

原生语音接口支持播放、暂停、继续、取消和声音选择，但**可用声音、音质、语速效果与暂停恢复表现要在本机验证**。浏览器接口也可能调用远端声音，因此不能承诺所有声音都离线运行；优先列出本地声音并标明来源。

M0 先验证这条路线。通过后，第一版先采用直接朗读，**不生成可下载的 MP3 文件，也不承诺首次打开后离线可用**。

若自然度或暂停稳定性不满足实际练习要求，则在 M0 调整为“语音服务生成每句音频并缓存 → HTMLAudioElement 播放”。仍沿用同一套界面和句子数据。具体服务、费用及文本处理方式届时再按需求选择；本轮没有接入或调用付费服务。

这个方案可以练文字对应、辨音与听写。合成语音与真实对话的连读、口音及语境有差别；以后如果要练真实材料，可以再增加“音频＋原文导入及时间对齐”，作为独立阶段实现。

### 为什么暂时不需要音频时间戳

当前输入是文字，可以先分成句子，再让语音逐句读。上一句和下一句只需要切换句子编号，不必在一整段音频中猜测起止位置。

以后导入真人音频时，才需要处理“某句话对应音频中哪几秒”。这与本轮的文字断句是不同问题。

## 5. 实现时要明确的规则

### 断句

- 先清理换行、UTF-8 BOM 等格式问题，保留原始全文；按段落使用 `Intl.Segmenter` 的 sentence 粒度切分。
- 使用 `Dr. Smith`、`3.14`、引号、问号、感叹号等样例检查效果，不承诺自动规则百分百正确。
- 无标点或明显过长的句子显示待调整提示，不按字符数任意截断单词。
- 自动预览后允许用户改成“一行一句”，用简易文本编辑完成拆分和合并。
- 开始练习后如重新编辑原文，先停播并生成新句子列表，重置当前句；已有听写草稿保留。

### 播放

- 由一个播放控制模块持有语音实例和重复计时器，界面组件通过它发命令。
- 每次切句、切材料或停止时取消旧语音和计时器；使用递增会话编号，忽略旧的结束回调，防止旧句再次出声。
- 普通播放结束后停止；点击“重复三次”始终从第一遍重新计数，先前已听的一部分不计入。
- 重复期间可暂停，包括句间等待阶段；恢复后继续剩余遍数，句间暂停恢复时重新等待完整间隔。
- 改语速或声音时结束旧播放；播放中则以新设置从当前句开头重播，暂停中则等下一次点击播放再重播；重复计数重新开始。
- 先完整验证“第一句、最后一句、快速连点切句、第三遍结束、暂停后切句”等边界，再扩展功能。

### 听写与保存

- 草稿独立于播放器状态，重听、切句和隐藏原文都不能清空。
- 保存失败时显示失败状态并保留当前页面内容，提供导出；不得显示“已保存”假成功。
- 备份包含版本号、原文、分句结果、草稿与位置；导入先校验格式，再让用户选择追加或替换，不静默覆盖。
- 文本仅作为文本渲染，不把导入内容作为 HTML 执行。
- 稳定使用相同的本地地址和端口，避免不同来源导致“存储不见了”。浏览器清理数据或换浏览器后，用备份恢复。
- 输入法组合输入期间不触发快捷键；不占用普通空格及 Ctrl+Z 等编辑操作，按住快捷键不反复触发。

## 6. 分步开发：每步都能看见成果

下面是建议安排，不是已完成清单，也不预设每天可投入时间。

| 阶段 | 可验收成果 | 助手负责 | 用户动手部分 |
|---|---|---|---|
| M0 语音验证 | 三句样例可朗读、暂停继续、切句并重复三次；试听后确定声音路线 | 准备最小试验页、说明调用与事件，修复平台问题 | 试听声音；阅读控制流程，修改一个语速选项并验证 |
| M1 页面骨架 | 双栏页面显示三句文字，右侧可输入 | 搭建 React/TS/Vite、讲解入口与组件、示范一个按钮 | 实现“下一句”的编号变化及末句边界，按需要提供提示 |
| M2 精听控制 | 上下句、暂停、三次重复与语速在正式界面可用 | 将 M0 的可靠逻辑接到界面，处理回调与取消 | 实现“上一句”或原文隐藏，检查与已有功能的联系 |
| M3 自选材料 | 可粘贴或读入 TXT，自动断句并手动修正 | 实现文件读取与断句服务，解释字符串处理 | 完成空白文本校验或标题输入，并用自己的材料验证 |
| M4 保存练习 | 刷新恢复草稿和位置，备份可导出导入 | 实现存储与版本校验，处理异常 | 完成一种设置的保存与恢复，检查刷新效果 |
| M5 日常试用 | 用一篇真实材料完成完整练习，修复影响使用的问题 | 检查交互与界面，整理启动说明 | 实际精听并反馈卡点；独立修改一个小功能 |

学习节奏：每轮只选一个小输出，先给目标与输入输出，再按需要提示或示范。无需靠回忆旧项目证明基础，也不把助手写完的代码记作用户已掌握。

用户如果当次只想修复故障或拿到直接答案，就先完成实际工作。是否独立完成，依据本次代码与过程判断，不给能力贴标签。

## 7. 第一版验收清单

- [ ] 粘贴一篇真实英文材料，断句预览可修正，进入双栏练习。
- [ ] 当前句正常朗读，普通播放一句后停止；上一句、下一句与点击选句正常。
- [ ] 暂停再继续不漏句、不重叠；首尾不会越界，快速切句不会冒出旧语音。
- [ ] 重复三次完整播放恰好三遍，等待和播放期间均可暂停，结束后停下。
- [ ] 改语速、声音后遵守预定行为；实际声音满足用户试听要求。
- [ ] 输入听写时可使用快捷键，输入法与普通编辑操作不受影响。
- [ ] 原文可隐藏并查看当前句；听写草稿始终保留，输入焦点稳定。
- [ ] 刷新恢复草稿、材料和位置，页面不会自动出声；备份能导出并恢复。
- [ ] 空材料、无声音、无效文件、存储失败有可操作提示。
- [ ] 目标桌面窗口下控制区和两栏可用，完成一篇真实材料的练习。

验证方式：项目构建与类型检查；断句、播放器次数和取消等有意义的逻辑检查；浏览器实际走通导入、输入、保存等流程。语音自然度和真实暂停效果必须人工试听，自动化按钮检查不能替代。

## 8. 下一次从哪里开工

从 **M0 语音验证** 开始。助手准备三句原创英文的最小试验页，解释“文本 → 朗读任务 → 结束事件”，用户先试听，再改一个语速选项。声音路线验证通过后，再搭建正式工程。

当前工程已搭建，可双击根目录“启动练习.cmd”，或运行 `npm.cmd run dev`。语音路线保留试用状态，真实音质与暂停效果由用户试听确认。

## 9. 后续代码怎么拆

工程已按以下边界组织，部分界面暂集中在 App.tsx，后续结合用户动手任务继续拆分：

```text
src/
  App.tsx                    连接材料、当前句和练习状态
  components/
    ImportPanel.tsx          粘贴、TXT 导入与分句预览
    PlayerControls.tsx       播放、暂停、上下句与设置
    TranscriptPanel.tsx      原文列表与隐藏
    DictationEditor.tsx      听写输入与保存状态
  lib/
    segmentText.ts           文本清理、自动断句
    speechPlayer.ts          语音控制、重复计数与取消
    storage.ts               材料与练习记录读写
  types.ts                   共享数据类型
  styles.css                 页面样式
```

核心数据分成三组：

| 数据 | 主要字段 | 是否保存 |
|---|---|---|
| Material 材料 | id、title、language、sourceText、sentences、revision | 是；每句至少包含稳定 id 与 text |
| Practice 练习 | materialId、draftText、currentSentenceId、updatedAt | 是；分句修改后重新校验当前句 |
| Preferences 设置 | voiceURI、rate、原文显示偏好 | 是；声音不存在时重新选择并提示 |

“正在播放、暂停、句间等待、已播次数、错误、当前播放会话编号”等只属于运行状态，不保存为下次打开就会继续的任务。

数据包含 `schemaVersion`，浏览器存储使用项目专属键；导入备份先检查版本、字段与大小。声音使用持久标识保存，重新打开时再匹配本机可用声音，不能假设声音列表永远不变。
